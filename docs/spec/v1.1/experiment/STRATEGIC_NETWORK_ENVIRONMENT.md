# Strategic Network Environment

The first environment is synthetic because the experiment needs exact hidden state, exact provenance, repeatable counterfactual access, and known cases where resolution is or is not warranted.

It is not intended to simulate any particular real social platform or institution.

## Hidden world

A seeded hidden world contains:

- actors;
- private knowledge facts;
- actor goals/preferences;
- relationships;
- channel access/capabilities;
- source events;
- messages/actions;
- provenance graph;
- channel transformations;
- evidence artifacts available at different access levels;
- hidden evaluation targets with access-relative expected statuses.

## Case classes

Every generated qualification world declares one hidden case class:

### `resolvable`

The current visible evidence contains enough information to warrant at least one material distinction. A solver that always hedges should fail these cases.

### `non_identifiable`

At least one predeclared material distinction cannot be resolved under the current access regime. A solver that confidently chooses one side should fail these cases.

### `transition`

The initial evidence is intentionally insufficient, but a later reveal or available evidence action makes the distinction resolvable. These cases test updating rather than static classification.

The hidden expected statuses are evaluation metadata only and never appear in investigator prompts.

## Required strategic features

Across the qualification suite, include:

1. actors with overlapping but nonidentical knowledge;
2. actors capable of producing superficially similar observations for materially different reasons;
3. provenance chains where multiple surface observations descend from one source;
4. genuinely independent corroboration;
5. spoof/mimicry or plausible source-confusion events;
6. both resolvable and intentionally unresolved material distinctions;
7. evidence actions that separate at least some initially ambiguous worlds;
8. attractive early explanations invalidated by later evidence;
9. actor behavior that changes in response to an investigation action or newly public information;
10. causally irrelevant but plausible background observations.

Not every individual world must contain every feature. The seed-suite generator records feature coverage and the qualification suite must cover all ten.

## Scale profiles

### Smoke

- ~5 actors
- ~20 observations
- 2 evidence rounds
- 3–5 candidate worlds

Purpose: implementation/debugging only.

### Small

- ~20 actors
- ~150 observations
- 4–6 evidence rounds
- initial candidate fan-out 8–16
- visible evidence target roughly 10k–25k tokens after rendering

### Medium — default Gate 1 target

- ~40 actors
- ~400 observations
- 5–7 evidence rounds
- initial candidate fan-out 12–24
- maximum alive worlds expected 32–96
- visible evidence target roughly 30k–70k tokens

### Large — stress / long-investigation target

- ~80 actors
- ~1000 observations
- 6–8 evidence rounds
- initial candidate fan-out 16–32
- maximum alive worlds expected 64–128
- visible evidence target roughly 80k–160k tokens

These are planning profiles, not scientific constants. The runner records actual rendered token counts. Do not interpret a small-profile failure as evidence against a claim that only predicts an advantage at larger persistent-state loads.

## Event generation

The causal event/provenance structure is generated by code from the seed. Surface text may initially use templates. Optional LLM surface rendering can be added only if it preserves hidden event identity and is unnecessary for simulator correctness.

## No LLM-authored hidden truth

The hidden causal world must be represented independently of the model being evaluated. An LLM may render text, but it cannot decide after the fact what “really happened.”

## Evidence action examples

- authenticate the source of message M;
- reveal whether observations E12/E44 share a provenance root;
- reveal actor A's access to fact X before time T;
- inspect channel delivery metadata for observation E77;
- reveal the original source text behind a paraphrase;
- inspect one actor-to-actor communication edge;
- reveal a timestamped event log.

## Evaluation-target authoring

Each world includes a small hidden list of material propositions. For each access regime/round where it is scored, each proposition is labeled by the environment as `supported`, `rejected`, or `unresolved`. These labels are generated/validated from the simulator construction, not by the evaluated model.

The purpose is to score both premature certainty and pathological hedging.
